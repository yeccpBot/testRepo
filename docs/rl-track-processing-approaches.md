# 航迹处理端到端神经网络：强化学习可行方案

本文档整理用强化学习（RL）构建航迹处理模块端到端神经网络的几条可行路线，比较各自的难度与风险，并给出建议的实施顺序。仓库当前的代码骨架（仿真环境、卡尔曼滤波基线）对应下文的“阶段 0”。

## 1. 问题定义

航迹处理模块的输入是传感器（雷达、ADS-B、光电等）逐帧输出的点迹（量测），输出是带编号的目标航迹。传统流水线通常包括：

| 环节 | 作用 | 典型传统方法 |
| --- | --- | --- |
| 航迹起始 | 从未关联点迹中确认新目标 | M/N 逻辑、Hough 变换 |
| 数据关联 | 决定哪个点迹属于哪条航迹 | 最近邻（NN/GNN）、JPDA、MHT |
| 滤波与预测 | 估计目标位置、速度 | KF / EKF / UKF、IMM |
| 航迹管理 | 维持、合并、终止航迹 | 计分、丢失计数 |
| 多目标整体 | 统一建模目标数和状态 | PHD / CPHD、PMBM 等随机有限集方法 |

“端到端神经网络”指用一个（或少量联合训练的）网络替代上述全部或大部分环节：输入点迹序列，直接输出航迹集合。

### 1.1 强化学习适合解决什么

需要先明确一点：如果仿真能给出真值，**状态估计本身是监督学习问题**，直接用真值做回归通常比 RL 更省样本、更稳定。RL 的价值集中在以下几类问题上：

- **离散的序贯决策**：关联、起始、终止是离散选择，且当前选择会影响之后若干帧，这正是 MDP 的形态。
- **不可微的评价指标**：OSPA/GOSPA、航迹断批次数、ID 切换次数、虚假航迹率等指标无法直接求梯度，可以作为 RL 奖励。
- **长期权衡**：例如“晚一帧起批换取更低虚警率”，这类取舍可以通过奖励权重显式表达。
- **闭环资源调度**（若后续扩展）：传感器波束/驻留调度会影响未来的观测，属于典型 RL 问题。

因此下面的方案大多采用“监督学习打底 + RL 优化决策或整体指标”的组合，而不是从零开始纯 RL。

## 2. MDP 建模要素

各方案共用的建模思路如下，具体取值随方案变化。

- **状态/观测**：当前帧点迹集合（位置、多普勒、SNR、时间戳）、已有航迹的预测状态与协方差、航迹历史特征（存活帧数、连续丢失帧数等）。点迹和航迹数量可变，需要用集合/序列编码器（Transformer、DeepSets、图神经网络）处理。
- **动作**：
  - 连续动作：状态修正量、滤波器参数（Q、R 缩放，IMM 转移概率）。
  - 离散动作：点迹-航迹关联矩阵中的选择、起始/确认/删除航迹。
- **奖励**（按帧或按回合）：
  - 估计精度：`-||x_est - x_true||` 或 `-GOSPA`。
  - 航迹质量：漏跟惩罚、虚假航迹惩罚、ID 切换惩罚、起批延迟惩罚。
  - 需要在仿真中保留目标真值 ID，才能计算这些项。
- **回合**：一段固定时长的场景（如 100～500 帧）。

## 3. 可行方案

### 方案 A：混合架构，RL 只负责航迹管理与关联决策

保留卡尔曼/IMM 滤波，网络只替换决策环节：

- 关联：策略网络对每条航迹输出“关联到哪个点迹 / 不关联”，可用 Transformer 对航迹-点迹对打分，再经匈牙利算法或逐条采样得到动作。
- 管理：每条航迹一个离散动作 `{保持, 确认, 删除}`，奖励来自航迹级真值匹配。
- 算法：PPO（离散动作）或 DQN 系列；每条航迹看作一个智能体时可用 MAPPO 这类参数共享的多智能体 PPO。

优点：滤波部分可解释、有理论保证；动作空间小，训练稳定；可以逐个环节替换并与传统方法对比。
缺点：不是严格意义上的端到端；精度上限受滤波模型限制。
参考：Xiang 等把单目标的生命周期（激活、跟踪、丢失、终止）建模为 MDP（ICCV 2015）；Ren 等用协作式深度 RL 处理多目标跟踪中的决策（ECCV 2018）。两者是视觉 MOT 场景，但建模方式可以迁移到点迹航迹。

### 方案 B：RL 自适应调节滤波器

滤波结构不变，策略网络根据新息序列等特征，每帧输出滤波参数：过程噪声 Q 的缩放因子、量测噪声 R 的缩放因子、IMM 模型转移概率，或直接输出卡尔曼增益修正量。

- 算法：连续动作，PPO 或 SAC。
- 奖励：估计误差，以及新息一致性（NIS）偏离程度。

优点：改动最小，最容易上线；对机动目标、非高斯噪声有明显收益空间。
缺点：只覆盖滤波环节；如果有真值，KalmanNet 这类直接监督学习增益的方法可能更省事，RL 版本的优势需要实验证明。
参考：KalmanNet（Revach 等，IEEE TSP 2022）用 RNN 学习卡尔曼增益，可作为本方案的监督学习对照。

### 方案 C（推荐主线）：端到端网络，监督预训练 + RL 微调

一个网络直接完成“点迹序列 → 航迹集合”：

1. **网络结构**：以帧为步长的循环式 Transformer。每帧把当前点迹编码为 token，与上一帧的“航迹查询向量”（track query）做注意力交互；每个 track query 输出该航迹的状态、存在概率，新目标由新生查询产生。视觉领域的 TrackFormer（CVPR 2022）、MOTR（ECCV 2022）采用的就是这种 track query 机制，可以直接借鉴到点迹数据上。
2. **监督预训练**：在仿真数据上，用匈牙利匹配把预测航迹和真值目标配对（DETR 式集合损失），对状态做回归、对存在概率做分类。这一步解决“能跟上”。
3. **RL 微调**：把网络看作策略，存在概率与关联选择作为随机动作，以 GOSPA、ID 切换、断批、虚警等不可微指标为奖励，用 PPO 微调。这一步解决“按业务指标跟得好”，比如减少断批、平衡起批速度与虚警。
4. 微调时加入与预训练策略的 KL 约束，防止策略崩坏。

优点：真正端到端；监督阶段保证样本效率，RL 阶段对齐业务指标；结构可扩展到多传感器融合。
缺点：工程量最大；需要高质量、可控的多目标仿真器；RL 微调阶段的奖励设计和稳定性需要反复调试。

### 方案 D：纯强化学习端到端

不做监督预训练，策略直接从点迹输出状态估计和关联决策，奖励即估计误差和航迹质量。

优点：不依赖逐帧真值标注的格式，理论上可以只依赖回合级评价。
缺点：样本效率很低；连续估计的信用分配困难；在有真值的条件下，几乎总是不如方案 C。建议只在小规模单目标环境中做对照实验（仓库的 `SingleTargetTrackingEnv` 即可用于此），不作为主线。

### 方案 E：离线强化学习（数据驱动）

如果难以构建逼真仿真器，但有大量历史点迹记录和现有跟踪器的输出（可视为行为策略），可以用离线 RL（CQL、IQL 等）从记录数据中学习关联与管理策略。

优点：直接使用真实数据，没有仿真-真实差距。
缺点：真实数据往往没有目标真值，奖励难以定义（需要人工标注、高精度参考源如 ADS-B，或事后平滑结果作为伪真值）；策略只能在数据覆盖的范围内改进。
适用：作为方案 A/C 的补充，在真实数据上做适配。

## 4. 方案对比

| 方案 | 端到端程度 | 样本效率 | 训练稳定性 | 工程量 | 可解释性 | 主要风险 |
| --- | --- | --- | --- | --- | --- | --- |
| A 混合决策 | 低 | 高 | 高 | 中 | 高 | 精度受滤波模型限制 |
| B 自适应滤波 | 低 | 高 | 高 | 低 | 高 | 相对 KalmanNet 优势不明确 |
| C 监督 + RL 微调 | 高 | 中 | 中 | 高 | 低 | 仿真器质量、奖励设计 |
| D 纯 RL | 高 | 低 | 低 | 中 | 低 | 难以收敛 |
| E 离线 RL | 中 | 取决于数据 | 中 | 中 | 中 | 缺乏真值和奖励 |

## 5. 建议路线

1. **阶段 0：仿真与基线**（仓库已有雏形）
   - 单目标 2D 匀速模型仿真环境 `SingleTargetTrackingEnv`，与卡尔曼滤波基线。
   - 接下来补充：多目标、杂波（泊松分布虚警）、检测概率 Pd < 1、机动模型（CT/CA）、目标出生/消亡。
   - 实现评价指标：位置 RMSE、OSPA/GOSPA、航迹完整率、断批次数、ID 切换、虚假航迹率、起批延迟。
   - 传统基线：GNN + KF/IMM，必要时 JPDA 或 PMBM，作为所有学习方法的比较对象。
2. **阶段 1：方案 B 与方案 D 小实验**：在单目标环境上用 PPO/SAC 跑通训练流程，验证奖励、归一化和评估管线，结果对照卡尔曼滤波。
3. **阶段 2：方案 A**：在多目标杂波环境中用 RL 学习关联与航迹管理，对比 GNN/JPDA。
4. **阶段 3：方案 C**：搭建 track query Transformer，先监督预训练达到接近基线的精度，再用 PPO 按 GOSPA 和航迹质量奖励微调。
5. **阶段 4：真实数据适配**：按第 6 节的数据策略，用 AIS 驱动的仿真扩大训练数据，用雷达实测点迹校准仿真器并微调、评测模型；仍有仿真-真实差距时，引入领域随机化或方案 E。

每个阶段的通过标准都以“相对传统基线的指标提升”衡量，而不是只看训练奖励曲线。

## 6. 数据策略：仿真预训练与实测校准

### 6.1 借鉴 AutoTavern 的思路

[AutoTavern](https://github.com/MCG-NJU/AutoTavern)（南京大学 MCG，论文 *Build, Don't Play*，arXiv:2610.33845）面向《炉石传说：酒馆战棋》，用 PPO 训练出了水平超过天梯头部玩家的 AI。它和本项目的场景不同，但有几条做法可以直接迁移：

| AutoTavern 的做法 | 对本项目的对应做法 |
| --- | --- |
| 先投入精力做一个**忠实、快速、确定性**的模拟器 TavernGym，再在上面训练 | 仿真器是本项目的核心资产，优先级不低于网络结构；要支持固定随机种子复现、批量并行推进 |
| 观测只包含真实客户端能看到的信息 | 仿真环境只给网络真实雷达能输出的量（点迹、SNR、多普勒、时间戳），不泄露真值 |
| 对手策略**按真实对局校准**，再用 PPO 对着校准后的对手训练 | 先用实测数据校准仿真器（量测误差、检测概率、杂波），再在校准后的仿真里训练，而不是只在训练完成后微调网络 |
| 状态可精确保存、恢复、分叉推演 | 环境支持保存/恢复场景状态，便于复现失败案例、对同一场景做对比实验 |
| 上线实战形成闭环：真实反馈用来修正模拟器、对手和策略 | 实测评测中发现的失败模式，回头修正仿真器，再重新训练 |
| 固定评测基准 TavernBench（960 道任务、40 个场景），每个结论都要通过验证 | 建立固定的航迹评测集（交叉、并行、机动、密集杂波、遮挡等场景），任何改进都以该评测集上的指标为准 |

### 6.2 是否应该“仿真数据训练 + 实测校准”

应该，这是本项目最可行的路线。原因有两点：

- 强化学习需要大量与环境交互，只能在仿真中进行；实测数据是固定的记录，无法让策略“试错”。
- 实测数据通常缺少完整真值，样本量也有限，不足以从零训练端到端网络。

“校准”分为两层，应先做第一层：

1. **校准仿真器**（系统辨识）：用实测点迹统计雷达的距离/方位误差及其随距离、SNR 的变化、系统偏差、检测概率、杂波密度与空间分布、扫描周期与时间抖动，并写回仿真器参数。之后的训练都在校准后的仿真中进行。
2. **校准模型**：在有参考真值的实测片段上做监督微调；没有真值的部分只能用于离线评估或离线 RL（方案 E），不能直接作为 RL 在线训练环境。

### 6.3 用 AIS 数据作为仿真源

可行，而且适合船舶目标。做法是“真实轨迹 + 仿真量测”：

- **轨迹来自 AIS**：AIS 提供船舶自报的位置、航速、航向，可以替代仿真中人为设定的运动模型。真实船舶的转向、变速、会遇、靠泊行为都包含在内，比匀速/协调转弯模型更接近实际。公开数据源有美国 MarineCadastre、丹麦海事局等发布的历史 AIS 数据。
- **量测由雷达模型生成**：把 AIS 轨迹插值到雷达扫描时刻，按 6.2 中校准好的误差模型加噪，按检测概率随机漏检，再叠加杂波，得到仿真点迹。这样数据量可以很大，同时每个点迹都有真值和目标 ID，可直接用于监督预训练和 RL 奖励计算。

使用 AIS 需要处理的问题：

- **AIS 本身不是精确真值**：存在 GPS 定位误差、上报间隔不均（航行中的 A 类设备约 2～10 秒一次，B 类和锚泊船舶间隔更长）、时间戳错误、MMSI 重复或伪造。需要先清洗、平滑和插值。
- **只覆盖装有 AIS 的船**：小艇、渔船、非合作目标往往没有 AIS。仿真时需要额外加入无 AIS 的目标，否则网络学不到这类目标。
- **场景范围**：AIS 只适用于海面目标；如果项目还涉及空中目标，需要 ADS-B 或其他轨迹源。

### 6.4 在 AIS 仿真基础上用雷达实测点迹校准

这是最有价值的一步，关键是拿到**同时段、同海域**的雷达点迹和 AIS 记录：

1. **AIS-雷达配准**：先补偿时间差和雷达站坐标/北向偏差，再把 AIS 轨迹与雷达点迹关联，得到“实测点迹 + 近似真值”的数据集。
2. **用配准数据校准仿真器**：统计真实的量测误差分布、检测概率曲线和杂波特性，替换仿真器中的假设参数（对应 6.2 第一层）。
3. **用配准数据微调和评测模型**：对有 AIS 匹配的目标做监督微调，并作为实测评测集。
4. **处理无 AIS 匹配的雷达航迹**：这类航迹可能是虚警，也可能是无 AIS 的真实目标，不能直接当作虚警惩罚。训练时应把它们标记为“未知”，从损失或奖励中屏蔽，或另行人工标注。

### 6.5 建议的数据分层

| 层级 | 数据 | 用途 |
| --- | --- | --- |
| L1 参数化仿真 | 运动模型生成的轨迹 + 仿真量测（仓库当前的环境） | 开发调试、单元测试、算法快速验证 |
| L2 AIS 驱动仿真 | AIS 真实轨迹 + 校准后的雷达量测模型 + 杂波 | 大规模监督预训练、RL 训练环境 |
| L3 实测数据 | 雷达实测点迹 + 同步 AIS | 校准仿真器、模型微调、最终评测 |

训练主要在 L2 上进行，L3 只用于校准和评测。在 L3 上发现的问题，优先回头修正 L2 仿真器，再重新训练。这个闭环对应 AutoTavern 用真实对局持续修正模拟器的做法。

## 7. 主要风险

- **仿真-真实差距**：杂波分布、检测概率、量测误差与真实传感器不一致时，学到的策略可能失效。对策是用实测数据校准仿真器（第 6 节）、领域随机化，并尽早接入真实数据验证。
- **奖励设计**：多个惩罚项的权重会直接决定策略偏好（例如过度删除航迹以减少虚警）。需要固定一套评测指标，与训练奖励分开报告。
- **可变数量的目标与点迹**：网络必须对集合大小和顺序不敏感，推荐注意力或图结构，避免固定长度输入。
- **实时性**：Transformer 在点迹密集时计算量增长较快，需要尽早确认帧率和硬件约束。
- **可解释性与验证**：纯网络航迹难以给出协方差等置信度信息；如果下游需要协方差，网络要额外输出不确定度。

## 8. 需要确认的问题

以下信息会影响方案选择，建议尽早确认：

1. 传感器类型和量测维度：雷达（距离/方位/俯仰/多普勒）、ADS-B、光电，或多传感器融合？
2. 单目标还是多目标，典型目标数量和杂波密度是多少？
3. 是否有真实数据？真实数据是否有真值或高精度参考？雷达点迹记录能否拿到同时段、同海域的 AIS 数据？
4. 实时性要求：帧率、延迟上限、部署硬件。
5. 最看重的指标：精度、起批速度、断批率还是虚警率？
6. 是否必须完全端到端，还是允许保留部分传统模块（方案 A/B）？

`SingleTargetTrackingEnv` 的设定：观测为归一化的新息（量测减预测位置）和预测速度；动作为对匀速预测的修正量（归一化到 [-1, 1]）；奖励为负的归一化位置误差。策略在该环境中扮演“学习得到的滤波更新”，可以直接用于方案 B/D 的初步实验。
